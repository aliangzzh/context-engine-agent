# 工具参数抽取（function calling 的 arguments 那一步）

## 规则（检查清单）

1. 工具的每个参数都必须由**抽取器**从自然语言里产出；**不要**把整句用户输入塞进第一个参数。
2. 抽不出来 → 返回**追问**（"请补充城市"），而不是带一个错的参数去调工具。
3. 搜索类工具是**例外**：它要的就是整句问题，直接把用户原话当 query。
4. 抽取器必须有**定点单测**：正例（能抽到）+ 反例（不该抽的不抽）。
5. 工具执行失败不能崩掉 Agent 循环——`Tool.run` 统一兜底成一句人话。

## 反例（本仓库真实发生过）

**① 假参数：看着跑通了，其实结果全错**

- 现象：问"北京今天天气怎么样"，工具返回 `未找到城市「北京今天天气怎么样」`
- 根因：把整句用户输入直接当 `city` 参数传给了天气工具
- 修复：`backend/app/agents/tools.py` 的 `extract_args()` 负责抽参数，抽不到返回空 dict，
  由 `orchestrator._missing_args_hint()` 给出追问
- 验证：`backend/tests/test_core.py` 里工具参数抽取的定点单测（含"冷暖/下雨"这类没写"天气"的问法）

**② 中文运算符被漏掉**

- 现象：「12乘34加5等于多少」走不到计算器
- 根因：只认 `*` `/`，不认「乘 / 加 / 除以」
- 修复：先做全角与中文运算符归一化再抽表达式
- 验证：`tests/test_core.py` 的定点单测

**③ 归一化不彻底导致算错**

- 现象：「（18+6）乘以3」被抽成 `18+6`，算出 24（正确答案 72）
- 根因：全角括号没还原成半角，表达式在括号处被截断
- 修复：全角括号/运算符统一翻译后再抽；括号不配平就放弃抽取
- 验证：`tests/test_core.py`

**④ 误判：把商品词当成算式**

- 现象：「加绒牛仔」里的「加」被当成加法
- 根因：关键词匹配太宽
- 修复：中文运算符必须夹在数字之间才算（正则约束）
- 验证：`tests/test_core.py`

## 怎么自查你正在犯这个错

- 工具返回里出现**整句用户问题**（说明没抽参）
- 参数抽错时**没有追问**，流程"跑通"了但答案是错的
- 给抽取器加反例测试时，发现它把不该匹配的词也匹配了
