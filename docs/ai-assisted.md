# AI 辅助编程：怎么用、怎么验证

> 结论先写：AI 负责"写出第一版"，人负责"定义验收标准 + 验证 + 讲清楚每一行"。
> 下面这些标准，就是这个仓库自己的开发过程。

## 1. 用法：先给约束，再要代码

给 AI 的输入不是"帮我写个上传接口"，而是四件事：

1. **上下文**：要用哪个框架、哪个模块、现有代码长什么样（例如"沿用 `app/api.py` 的
   `(status, envelope)` 约定，不要引入新依赖"）；
2. **验收标准**：例如"错误码必须是 40001/41500，且 `tests/test_api.py` 里要能覆盖"；
3. **边界**：例如"离线环境，不能装 `python-multipart`，所以自己解析 multipart"；
4. **产出形态**：要可运行的代码 + 测试 + 文档，不要只有代码。

## 2. 验证：四层，缺一层都不算完

| 层 | 手段 | 本项目的例子 |
|---|---|---|
| ① 类型/语法 | `vue-tsc --noEmit`、`python -m compileall`/`ruff check` | 前端 137 个文件类型检查通过 |
| ② 单元测试 | `python -m unittest discover -s tests` | 85 个测试，覆盖上下文裁剪、存储事务、缓存、参数抽取、错误码 |
| ③ 接口/端到端 | 真起服务再发请求（`tests/test_api.py` 用 urllib；本地用 curl） | `/api/kb/upload` 走 multipart → 200 入库；`/api/kb/list?page=0` → 400/40001 |
| ④ 人工读代码 | 逐行问"这行为什么存在、删掉会怎样" | 见下面第 3 节 |

## 3. 读代码时要盯的四类问题（本仓库真实修过的）

1. **沉默的错误**：AI 常写 `except Exception: return {}`。本项目把"坏请求"改成显式
   `400 + 错误码`，把"超预算"改成 `over_budget` 如实上报 —— 不静默吞掉。
2. **跨线程/跨进程的假设**：SQLite 连接默认不能跨线程用，而 HTTP 服务器是多线程的
   （`sqlite3.ProgrammingError`）。修法是 `check_same_thread=False` + 锁，并补并发回归测试。
3. **假参数**：工具调用最初把整句用户输入当参数传，看着"跑通了"，其实结果全错
   （`未找到城市「北京今天天气怎么样」`）。现在 `extract_args` 负责抽参数，抽不到就问用户。
4. **前后端字段名漂移**：SSE 发的是 `used_tools`，前端读的是 `usedTools` —— 页面永远不显示
   工具调用。这类问题只有"跑起来看"或者"类型检查"才能发现。

## 4. 什么时候不信 AI 的输出

- 涉及**钱的**（token 成本、API 调用次数）：必须自己算一遍；
- 涉及**并发/事务**的：必须写并发或失败回滚的测试；
- 涉及**指标数字**的：对外只写真实跑出来的（"K=1 召回 90%→K=3 95%"是实测，不是生成的）；
- **外部 API 的参数**：以官方文档为准，AI 给的字段名经常是过期版本。

## 5. 这个仓库里 AI 参与的痕迹（可以自查）

- `backend/app/multipart.py`：为了不引入 `python-multipart` 手写的解析器；
- `backend/tests/test_api.py`：用 stdlib `urllib` 起真实 HTTP 的接口测试（因为装不了 httpx）；
- `frontend/src/router/index.ts`：离线环境下的 vue-router 等价实现；
- 这三个文件都是"约束优先"的产物：先定边界（不能装包、要能离线跑），再让 AI 写。
